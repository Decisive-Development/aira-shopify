HOW THE ARCHITECTURE WORKS (do not redesign it):
  - /qr/newsletter and /qr/tutorial are NOT pages. They are Shopify URL

1. NEWSLETTER POPUP  (homepage, trigger: #newsletter)
================================================================================

1.1  Trigger logic
────────────────────────────────────────────────
  - On page load of the HOMEPAGE: if location.hash === '#newsletter',
    open the email-capture popup (small delay ~300ms so first paint lands).
  - The hash trigger fires EVERY time — it must override any "user
    previously dismissed" suppression, because arriving with #newsletter
    is explicit intent (they scanned the insert to get the code).
  - Also expose a manual hook so future CTAs can open the same popup:
    any element with [data-open-newsletter] opens it on click.
  - No timed/auto popup on plain visits. The popup opens ONLY via hash or
    the data-attribute. (Homepage is a tight sales page — no popup spam.)

1.2  Popup structure
────────────────────────────────────────────────
  - Modal overlay: backdrop, centered card on desktop / bottom-sheet or
    centered on mobile — follow existing modal patterns in the theme
    (reviews modal exists; match its mechanics, not necessarily its look).
  - Dismiss: X button, ESC key, backdrop tap.
  - Accessibility: role="dialog", aria-modal="true", focus moves into the
    email input on open (keyboard opening on mobile is desired here),
    focus trap while open, body scroll locked.
  - Form: Shopify customer form —
      {% form 'customer' %}
        <input type="hidden" name="contact[tags]" value="newsletter, qr-insert">
        <input type="email" name="contact[email]" ...>
        submit button
      {% endform %}
    The `qr-insert` tag is the attribution layer — it marks every signup
    that came from the printed insert. Keep it exactly as written.
  - Success state (form posts back with success): swap form for a
    confirmation message inside the same popup. Do NOT display the
    discount code in the popup — the code arrives by email (that is the
    point of the capture). Already-subscribed emails get the same success
    state; do not build special handling.

2. TUTORIAL AUTO-PLAY  (/pages/how-it-works, trigger: #video)
================================================================================

2.1  Trigger logic
────────────────────────────────────────────────
  - On page load of /pages/how-it-works: if location.hash === '#video',
    open/activate the tutorial video and start playback.
  - First: inspect how the tutorial video is currently embedded on the
    page (modal? inline player? YouTube/Vimeo iframe? native <video> /
    Shopify-hosted?). ADAPT to what exists — do not re-embed the video.

2.2  Autoplay reality on mobile (non-negotiable constraints)
────────────────────────────────────────────────
  - iOS Safari and Android Chrome block un-muted programmatic autoplay.
    A QR scan arrival is NOT a user gesture on the video.
  - Native <video>: start with `muted` + `playsinline` attributes set,
    then .play(). Show a clear tap-to-unmute affordance on the player.
  - YouTube/Vimeo iframe: append autoplay=1&mute=1&playsinline=1 (YT) /
    equivalent Vimeo params when — and only when — the page loaded with
    #video.
  - If the video sits inline (not in a modal): also scroll it into view
    (scrollIntoView, centered) before playing.
  - Normal visits without the hash must behave exactly as today.
