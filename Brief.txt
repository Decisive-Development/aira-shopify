AIRA — POLICY PAGES: RENDER FROM SHOPIFY CMS, KEEP THE DESIGN — BRIEF FOR VSC
Date: 2026-07-29
Priority: HIGH (unblocks Google & YouTube app / GA4 / Merchant Center; fixes empty checkout policy links)
Scope: theme repo only. The policy CONTENT is being populated in Shopify admin separately by Tom/Cowork. Do not write policy copy.

== WHY ==

Shopify's native policy fields (Settings > Policies) were empty except Privacy. Shopify links
these in the CHECKOUT footer, so the live checkout showed only a Privacy policy link. Verified
29 Jul: /policies/refund-policy and /policies/terms-of-service both returned HTTP 404, while
/policies/privacy-policy served fine.

Meanwhile the real content lives in theme pages at /pages/refund-policy, /pages/terms-of-service,
/pages/shipping-policy, /pages/privacy-policy. Two homes for the same document, and the one
checkout and Google read was the empty one. Privacy has already drifted: native 28,041 chars vs
page 24,595 chars.

Fix: native policy fields become the SINGLE SOURCE OF TRUTH. The designed pages keep their design
and render the native content. This is the "never duplicate" rule applied to policy copy.

== THE CHANGE ==

Current rendered structure (measured live 29 Jul, identical across all four policy pages):

  <section class="relative bg-secondary text-main py-12 md:py-20">
    <div class="container mx-auto px-4 max-w-[1080px]">
      <div class="md:flex md:gap-12 lg:gap-16 md:items-start">
        <article class="policy-prose flex-1 max-w-[720px] font-body text-base md:text-...">
          ...page content...
        </article>
        <aside class="hidden md:block md:w-1/3 md:max-w-60 md:sticky md:top-24 md:self-start md:shrink">
          ...empty in server HTML, populated client-side (sticky TOC)...
        </aside>

KEEP the section, container, flex row, <article> and its classes, and the <aside> exactly as they
are. Replace ONLY the inner content of <article class="policy-prose"> with the matching Liquid
object:

  /pages/refund-policy      ->  {{ shop.refund_policy.body }}
  /pages/terms-of-service   ->  {{ shop.terms_of_service.body }}
  /pages/shipping-policy    ->  {{ shop.shipping_policy.body }}
  /pages/privacy-policy     ->  {{ shop.privacy_policy.body }}

Because .policy-prose styles its descendants (h2, h3, p, ul, li, table, a, strong, em), injected
CMS HTML inherits the design automatically. Expected result: pixel-identical rendering.

This is safe to do generically because the content carries almost no styling of its own. Tag
census inside .policy-prose, measured 29 Jul:

  refund policy      h2, p, a, em                                     0 elements with class/style
  terms of service   h2, h3, p, a, em, strong, br                     0 elements with class/style
  shipping policy    h2, h3, p, table/thead/tbody/tr/th/td            1 (div.policy-table-wrap)
  privacy policy     h2, h3, p, ul, li, strong, em, a, code, table    3 (div.policy-table-wrap)

== TWO IMPLEMENTATION NOTES ==

1. div.policy-table-wrap is the ONLY design-bearing element inside the content (horizontal scroll
   wrapper for tables on mobile). PREFERRED: make `.policy-prose table` responsive on its own
   (wrap via CSS, e.g. a scroll container on the table itself or display:block; overflow-x:auto)
   so the CMS only ever holds plain prose and a non-technical editor cannot break the layout.
   The pasted CMS HTML currently still contains the wrapper div, so the CSS must tolerate BOTH
   (wrapped and unwrapped tables) without double scrollbars.

2. The <aside> TOC is empty in server HTML, so it is built client-side from the headings inside
   .policy-prose. That keeps working unchanged. BUT verify nothing in Liquid reads `page.content`
   to build it. If anything does, repoint it at the policy object.
